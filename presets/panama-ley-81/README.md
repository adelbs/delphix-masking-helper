# Panama — Ley 81 de 2019

A profile set that finds Panamanian personal data in a database and masks it, built for
[Ley 81 de 26 de marzo de 2019 sobre Protección de Datos Personales](https://s3-legispan.asamblea.gob.pa/legispan/NORMAS/2010/2019/LEY/Administrador%20Legispan_28743-A_2019_3_29_ASAMBLEA%20NACIONAL_81.pdf)
(Gaceta Oficial 28743-A, in force since 29 March 2021) and its regulation, Executive Decree 285 of
28 May 2021. Data obtained through a prior dissociation or anonymization procedure falls outside the
law (art. 3, 5). The goal is a non-production copy that no longer identifies anyone: not only the
direct identifiers, but the quasi-identifiers that re-identify people in combination, the sensitive
data of article 4, section 11, the economic and financial data that article 8 puts under prior
consent, and criminal records.

## Detection

Every domain has a **Path** classifier on the column name, in Spanish, in the abbreviations of
Panamanian systems (`NUM_CEDULA`, `CIP`, `FEC_NAC`, `COD_CORREG`, `NIS`), in the fields of the
electronic invoice (`dRuc`, `dDV`) and in English. Names that are ambiguous on their own (`NOMBRE`,
`EXPEDIENTE`, `RESULTADO`, `CIUDAD`) carry a lower strength and need the values to agree; generic
ones exclude what they are not (`NOMBRE_PRODUCTO`, `CARGO_FIJO`, `DIRECCION_IP`).

Where the values have a recognizable shape or vocabulary, a **Regex** or **List** classifier finds
the data in columns whose name says nothing (`CAMPO1`, `OBS`, `TEXTO_LIBRE`): cédulas in every form
(`8-442-445`, `E-8-123456`, `4PI-234-123`), RUCs with their DV, names and surnames, e-mail,
Panamanian phone numbers, addresses, cards (Luhn), IPs, MAC and IMEI, plates, VIN, districts,
corregimientos and their INEC codes, indigenous peoples and languages, ICD-10 codes, medicines,
blood groups, religions, parties, social security coverage and social programs. A date written
`12-05-1985` has the shape of a cédula and is excluded.

**Type** classifiers rule domains out where the column cannot hold the data: a cédula is text of at
least 5 characters, a birth date a date, timestamp or text.

## Masking

All algorithms are deterministic for the engine's key, so the same value masks the same way in
every table and every job. Placeholders such as `N/D` or `-` do not fail a row: where there is
nothing to mask they pass through, and text in a key column that does not have the expected shape
is masked character by character instead of being left as it was.

### L1 — Direct identifiers

| Domain | Masking |
|---|---|
| `PA_L1_CEDULA` | Province mapped within 1–13, tomo and asiento digit by digit, letters kept; one-to-one. Driver's license columns too: the license number is the cédula |
| `PA_L1_RUC` | A natural person's RUC masked as the cédula, **valid DV recomputed**; a legal entity's RUC kept |
| `PA_L1_RUC_DV` | A DV in its own column: digits mapped (it cannot be recomputed from another column) |
| `PA_L1_NOMBRE`, `PA_L1_APELLIDO` | Word by word from Panamanian given-name and surname lists; a married woman's `de` kept |
| `PA_L1_NOMBRE_COMPLETO` | Given names and both surnames in Panamanian order, `… de Pérez` and `APELLIDOS, NOMBRES` too |
| `PA_L1_EMAIL` | Name and domain mapped character by character, top-level domain `.test` |
| `PA_L1_TELEFONO` | `+507` and the first digit kept, the rest masked; 7-digit landlines and 8-digit mobiles |
| `PA_L1_DIRECCION` | A fictitious Panamanian address: building, floor and apartment, or barriada and house |
| `PA_L1_TARJETA` | Payment Card (Luhn stays valid), including the MIDES Tarjeta Clave Social |
| `PA_L1_IP` | Each IPv4 octet mapped to 1–254 |
| `PA_L1_PLACA` | Serial letters and digits mapped, category letters (`T` taxi, `CD` diplomatic…) kept |
| `PA_L1_GEOLOCALIZACION` | Integer part and first decimal kept (about 11 km), the rest masked |
| `PA_L1_TEXTO_LIBRE` | Free Text Redaction: cédulas, e-mail, phones, cards, plates, IPs, names |
| `PA_L1_CREDENCIAL` | Every character becomes `X` |
| Passport, immigration document, social security number, idoneidad, bank account, device, VIN, finca, contract, user and address detail domains | Character Mapping: vowels to vowels, consonants to consonants, digits to digits; hex kept hex for devices |

### L2 — Quasi-identifiers

| Domain | Masking |
|---|---|
| `PA_L2_FECHA_NACIMIENTO` | Shifted up to 60 days |
| `PA_L2_FECHA_EVENTO` | Death, hiring, retirement, admission and similar dates, shifted up to 30 days |
| `PA_L2_ANIO_NACIMIENTO` | The decade stays, the last digit is masked |
| `PA_L2_EDAD` | The decade stays (37 → 3x); 100 and over becomes 90 |

| `PA_L2_DISTRITO` | Districts under 20,000 become the nearest one of the same province with at least 20,000 |
| `PA_L2_CODIGO_LUGAR` | INEC corregimiento and district codes, by the same rules |
| `PA_L2_LUGAR_POBLADO` | The name of a corregimiento of over 20,000 |
| `PA_L2_BARRIADA` | A common barriada name |
| `PA_L2_CODIGO_POSTAL` | The first two digits stay, the rest become zeros |
| `PA_L2_SEXO` | Replaced within its own vocabulary |
| `PA_L2_DEPENDIENTES` | Capped at 5 |
| nationality, marital status, occupation, employer, schooling, school | Replaced from a list |

### L3 — Sensitive data (art. 4, 11)

The categories of the law — racial or ethnic origin, religious, philosophical and moral beliefs,
union membership, political opinions, health, sexual preference or orientation, genetic and
biometric data — and, because the list is not exhaustive, gender identity and sexual life.

Categorical columns keep their shape: a yes/no flag stays a flag in the same vocabulary, a numeric
code gets other digits, and any other value is replaced from a list of the category (the
indigenous and Afro-descendant groups of the 2023 census, indigenous languages, ICD-10 codes and
diagnoses, medicines, the disability types SENADIS certifies, religions, political parties). Where
the values share no vocabulary — reproductive and mental health, sexual life, philosophical
beliefs, union membership — they are suppressed to `Sin información`. Biometric and genetic data
become `X`.

### FIN — Economic and credit data (art. 8, 3; Law 24 of 2002)

APC credit references (scores keep their digits' shape, statuses are replaced), debt, salary,
assets and pensions (mapped into plausible ranges in balboas), Social Security Fund coverage, MIDES
and IFARHU programs, poverty status and income quintiles, and housing tenure.

### PENAL — Criminal records (art. 30)

Records replaced by a generic status, flags kept as flags; case file numbers masked character by
character.

## The RUC check digit

A natural person's RUC carries a two-digit DV that the DGI computes over a 21-position table: the
cédula fields right-aligned in fixed widths (asiento 5, tomo 3, a code for the letters, province
2) and a constant 5, weights from 2 at the right, modulo 11, twice. Fields longer than their width
push the ones to their left. The plugin's Check Digit framework can do none of that.

The set computes it with tables. After the cédula is masked, a three-character state — weighted
sum, digit sum and position — travels through the value from right to left, each step a Data
Cleansing that turns *character + state* into *new state + character*; a final table turns the
state into the DV, and a second pass carries the DV back to where the old one was. The steps are
Regex Decompose algorithms joined in String Algorithm Chains of at most eight, the engine's limit.
The traveller was checked against the published algorithm on 20,000 random cédulas of every kind
before it became tables.

Every masked RUC has a valid DV, the mapping is one-to-one, and the cédula inside a masked RUC is the
masked cédula.

## Limits

- **Binary columns** (photos of the cédula, fingerprints, clinical PDFs in BLOBs) cannot be masked
  by these algorithms. Inventory them and report them as residual risk.
- **A DV in its own column** is masked, not recomputed, and no longer matches the masked RUC.
- **Cédula letters stay**: `PI` still marks an indigenous registration and `E`, `N`, `PE` a
  foreign, naturalized or born-abroad status. Changing them would break the format or collide.
- **Zero-padded or unhyphenated cédulas** (`08-442-445`) and `NT` RUCs are masked character by
  character without recomputing the DV.
- **A legal entity's RUC is kept**: it is not personal data under the law.
- **Data Cleansing leaves unknown values as they are**: a corregimiento spelled in a way that is not
  in the list passes unchanged.
- **Free text** is redacted token by token: a phone written with spaces is not found there, and a
  given name that is also a common word (`Luz`, `Rosa`) is redacted wherever it appears.
- **Minors**: a birth date moves at most 60 days, so few people cross their 18th birthday — but
  some do. Where that matters, split the rule by age group with Multi-Column Condition.
- **Addresses** are replaced as a whole line. Street, barriada, corregimiento and district kept in
  separate columns are masked independently.

## Checking

```bash
node presets/panama-ley-81/build.mjs
node presets/panama-ley-81/verify.mjs
node presets/_doc/build.mjs panama-ley-81
```

The last one regenerates the PDFs; run it after any change to the set or to `doc/`.

`verify.mjs` first checks its own DV computation against the published algorithm's examples. It
reviews every classifier configuration, profiles 138 columns with the whole set at its threshold —
well named, badly named and 24 columns that are not personal data — and masks 255 sample values
and 210 placeholders through the running app (`DLPX_URL`, default `http://localhost:3000`),
including RUCs in the four separators and five letter types, each checked for a valid DV. It then
masks 150 cédulas and 150 RUCs to check that none collide and every RUC keeps a valid DV, and 20
cédula and RUC pairs of the same person to check they still agree. Each value forks a JVM.
