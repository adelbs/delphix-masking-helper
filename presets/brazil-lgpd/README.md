# Brazil — LGPD (Lei 13.709/2018)

A profile set that finds Brazilian personal data in a database and masks it, built for the
[Lei Geral de Proteção de Dados Pessoais](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709compilado.htm)
(Lei 13.709/2018, as amended up to Lei 15.352/2026, which turned the ANPD into the Agência Nacional
de Proteção de Dados). Anonymized data is not personal data unless the anonymization can be reversed
with reasonable effort (art. 12). The goal is a non-production copy that no longer identifies anyone:
not only the direct identifiers, but the quasi-identifiers that re-identify people in combination and
every category of sensitive personal data of art. 5, II — racial or ethnic origin, religious
conviction, political opinion, membership of a trade union or of a religious, philosophical or
political organization, health, sexual life, genetic and biometric data — plus financial data and
criminal records.

## Detection

Every domain has a **Path** classifier on the column name, in Portuguese, in the prefixes of
Brazilian data models (`NR_CPF`, `NM_CLIENTE`, `DT_NASCIMENTO`, `CO_MUNICIPIO_IBGE`, `CS_RACA`,
`NU_CNS`, `SG_PARTIDO`) and in English. Names that are ambiguous on their own (`NOME`, `CARGO`,
`RESULTADO`, `PROCESSO`) carry a lower strength and need the values to agree; generic ones exclude
what they are not (`NOME_PRODUTO`, `RAZAO_SOCIAL`, `ID_MENSAGEM`).

Where the values have a recognizable shape or vocabulary, a **Regex** or **List** classifier finds the
data in columns whose name says nothing (`CAMPO1`, `OBS`): formatted CPF, CNPJ and PIS, given names and
surnames, e-mail, Brazilian phone numbers, street addresses, CEP, cards (Luhn), IPs, MAC and IMEI,
old and Mercosur plates, municipalities, colour or race, indigenous peoples, religions, parties,
trade unions, ICD-10 codes, medicines, blood groups, INSS benefit types and social programmes. Eleven
bare digits are a CPF, but also a mobile phone, a PIS, a CNH or a RENAVAM: they back up a column name
and decide nothing alone.

**Type** classifiers rule domains out where the column cannot hold the data: an e-mail is text of at
least 5 characters, a birth date a date, timestamp or text, an amount a number.

## Masking

All algorithms are deterministic for the engine's key, so the same value masks the same way in
every table and every job. Placeholders such as `N/I` or `-` do not fail a row: where there is nothing
to mask they pass through.

### Check digits

Brazilian applications validate their identifiers, so the ones with a public check-digit rule come out
**valid**, one-to-one and in the same format:

| Identifier | How |
|---|---|
| CPF | Two Check Digit algorithms, one inside the other (weights 10–2, then 11–2); formatted, bare, or with the leading zeros a numeric column dropped |
| CNPJ | Root masked, establishment order kept, both check digits recomputed — including the **alphanumeric CNPJ** of July 2026, weighed as ASCII minus 48 |
| PIS/PASEP/NIT/NIS | Check Digit with weights 3 2 9 8 7 6 5 4 3 2; the first digit stays |
| RENAVAM | Check Digit with the same weights; nine-digit numbers are padded |
| Voter card (título de eleitor) | State code kept; both check digits recomputed by Data Cleansing tables, including the São Paulo and Minas Gerais rule (remainder 0 gives 1) |
| CNS (definitive, 1 or 2) | The PIS part masked by the PIS algorithm, the tail recomputed by tables so the weighted sum stays a multiple of 11 — the masked CNS still carries the masked PIS |
| Payment card | Payment Card (Luhn) |

A column that holds CPFs and CNPJs together (`CPF_CNPJ`) is masked value by value by shape.

### L1 — Direct identifiers

| Domain | Masking |
|---|---|
| `BR_L1_CPF`, `BR_L1_CNPJ`, `BR_L1_PIS_NIS`, `BR_L1_TITULO_ELEITOR`, `BR_L1_RENAVAM` | Valid check digits (above) |
| `BR_L1_RG` | Digits mapped; the letters — the X check digit, `SSP/SP` — stay |
| `BR_L1_NOME`, `BR_L1_SOBRENOME` | Word by word from the 2022 census lists; `da`, `de`, `dos`, `e` and Júnior, Filho, Neto, Sobrinho stay |
| `BR_L1_NOME_COMPLETO` | Given names and surnames in Brazilian order; also mother's, father's and social names, and `SURNAME, GIVEN` |
| `BR_L1_EMAIL` | Name and domain mapped character by character, top-level domain `.test` |
| `BR_L1_TELEFONE` | `+55`, the DDD and the first digit (9 for mobile) kept, the rest masked |
| `BR_L1_ENDERECO` | A fictitious Brazilian address |
| `BR_L1_CHAVE_PIX` | By the kind of key: CPF, CNPJ, e-mail, phone or random key (UUID) |
| `BR_L1_CARTAO` | Payment Card (Luhn stays valid) |
| `BR_L1_IP` | Each IPv4 octet mapped to 1–254 |
| `BR_L1_PLACA` | Letters to letters and digits to digits, old and Mercosur patterns kept |
| `BR_L1_GEOLOCALIZACAO` | Integer part and first decimal kept (about 11 km) |

### L2 — Quasi-identifiers

| Domain | Masking |
|---|---|
| `BR_L2_DATA_NASCIMENTO` | Shifted up to 60 days |
| `BR_L2_DATA_EVENTO` | Death, admission, dismissal, hospitalization, arrest and similar dates, shifted up to 30 days |
| `BR_L2_ANO_NASCIMENTO` | The decade stays, the last digit is masked |
| `BR_L2_IDADE` | The decade stays (37 → 3x); 100 and over becomes 90 |
| `BR_L2_MUNICIPIO`, `BR_L2_CODIGO_MUNICIPIO` | Municipalities under 20,000 inhabitants (2022 census) become the nearest of the same state with at least 20,000 — by name, by name with the state, and by the IBGE code of 7 or 6 digits |
| `BR_L2_CEP` | The first three digits (the postal sector) stay; the rest becomes zeros |
| `BR_L2_SEXO` | Replaced within its own vocabulary, including the codes 1 and 2 |
| `BR_L2_DEPENDENTES` | Capped at 5 |
| neighbourhood, electoral zone, nationality, marital status, occupation and CBO, employer, education, school | Replaced from a list or digit by digit |

### L3 — Sensitive personal data (art. 5, II)

Colour or race (IBGE categories and codes), indigenous peoples and traditional communities, religion,
philosophical convictions and religious, philosophical or political organizations, political opinion,
party membership (the 30 parties registered with the TSE), trade union membership, genetic and
biometric data, sexual orientation and sexual life — and, beyond the list, gender identity.

Categorical columns keep their shape: a yes/no flag stays a flag in the same vocabulary, a numeric code
is replaced by another code of the same catalog, and any other value is replaced from a list of the
category. Where the values share no vocabulary — convictions, trade union, sexual life — they are
suppressed to `Não informado`. Biometric and genetic data become `X`.

### SAUDE — Health data (art. 5, II; art. 11)

The CNS with a valid check digit, medical record and hospitalization (AIH) numbers and health plan
cards, ICD-10 codes (with or without the dot) and diagnoses, medicines, clinical notes, test results,
blood group, disability, occupational health (ASO, CAT, sick leave), reproductive and mental health.

### FIN — Financial and credit data

Not sensitive under the LGPD, but under bank secrecy (Lei Complementar 105/2001) and credit reporting
rules (Lei 12.414/2011). Credit scores and negative records, debt, income, assets, benefit amounts, the
INSS benefit type — several reveal an illness, a disability or a pregnancy —, benefit numbers, social
programmes and the Cadastro Único, income brackets and socioeconomic classes, and housing.

### PENAL — Criminal records and court cases

Records replaced by a generic status, flags kept as flags; case numbers in the CNJ format keep year,
branch, court and origin and have the sequence masked.

## Municipalities

The set carries the population of the 5,570 municipalities of the 2022 census and their location.
3,860 have fewer than 20,000 inhabitants and become the nearest municipality of their own state that
has at least 20,000. The state itself is kept: the smallest, Roraima, has 636,707 people. A name shared
by several municipalities — or that differs from another only in accents — is generalized only when all
of them are small; written with its state (`Bonito - MS`, `Bonito/MS`) it is always generalized.

## Limits

- **Binary columns** (scans of RG and CNH, selfies from onboarding, fingerprints, clinical PDFs in
  BLOBs) cannot be masked by these algorithms. Inventory them and report them as residual risk.
- **CNH, RG, certificates, bank accounts and CNJ case numbers** have check digits the set does not
  recompute (state-specific rules, or rules Check Digit cannot follow); they are masked digit by digit.
- **Provisional CNS** (starting 7, 8 or 9) and CNS or voter cards written with spaces are masked digit
  by digit, without a valid check digit.
- **UF is not masked**, nor the DDD in a phone number, nor the bank code.
- **Data Cleansing leaves unknown values as they are**: a municipality spelled in a way that is not in
  the table passes unchanged.
- **Free text** is redacted token by token: a phone written with spaces is not found there.
- **Children and adolescents** (art. 14; Estatuto da Criança e do Adolescente, ECA Digital): a birth date
  moves at most 60 days, so few people cross their 12th or 18th birthday — but some do. Split the rule by
  age group with Multi-Column Condition where that matters.
- **The engine key** links masked values back to production for whoever holds both. With the key the
  result is pseudonymized data under art. 13, § 4 — still personal data —; keep the key away from the
  users of the masked copy.

## Checking

```bash
node presets/brazil-lgpd/build.mjs
node presets/brazil-lgpd/verify.mjs
node presets/_doc/build.mjs brazil-lgpd
```

The last one regenerates the PDFs; run it after any change to the set or to `doc/`.

`verify.mjs` reviews every classifier configuration, profiles 164 columns with the whole set at its
threshold and again with the essential pack — well named, badly named and 33 columns that are not
personal data — and audits the generalization table for all 5,570 municipalities. It then masks the
sample values, placeholders and each algorithm's own sample input through the running app
(`DLPX_URL`, default `http://localhost:3000`), checking outputs against their vocabulary and every
CPF, CNPJ, PIS, voter card, CNS and RENAVAM against its check-digit rule; 150 of each for collisions;
and 20 people whose PIS and CNS must still agree. Each value forks a JVM.
