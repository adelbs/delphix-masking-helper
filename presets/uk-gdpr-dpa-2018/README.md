# United Kingdom — UK GDPR and Data Protection Act 2018

A discovery policy that finds UK personal data in a database and masks it, built for the UK GDPR and
the Data Protection Act 2018 as amended by the Data (Use and Access) Act 2025. The goal is a
non-production copy that no longer identifies anyone: not only the direct identifiers — the National
Insurance number, the NHS number, the UTR, names, contact, bank details — but the quasi-identifiers
that re-identify people in combination (above all the **postcode**), the special categories of
Article 9, criminal offence data — which section 11(2) of the Act extends to **alleged** offences —
and financial data.

The law gives masking two anchors. Articles 25 and 32 of the UK GDPR name **pseudonymisation** among
the measures a controller should take, and **section 171** of the 2018 Act makes it a criminal offence
to knowingly or recklessly re-identify de-identified personal data without the consent of the
controller that de-identified it. Since 30 September 2026 the regulator is the **Information
Commission**, which replaced the ICO.

## Detection

Every data class has a **Path** classifier on the column name, in English and in the abbreviations of
UK systems (`NINO`, `NI_NO`, `NHS_NO`, `CHI`, `UTR`, `UPRN`, `MPAN`, `PNC_ID`, `DBS`, `DOB`). Names that
are ambiguous on their own (`NAME`, `RESULT`, `CITY`, `PARTY`, `TENURE`) carry a lower strength and need
the values to agree; generic ones exclude what they are not (`PRODUCT_NAME`, `MESSAGE_ID`, `PARTY_ID`).

Where the values have a recognizable shape or vocabulary, a **Regex** or **List** classifier finds the
data in columns whose name says nothing (`FIELD1`, `PFNOM`, `REMARKS`): National Insurance numbers
(without the prefixes HMRC does not issue), **NHS numbers that pass their modulus 11 check**
(`MOD11_NHS`), UTRs, DVLA licence numbers, given names and surnames, full names, e-mail, UK phone
numbers, addresses, **postcodes**, sort codes, **IBANs that pass ISO 13616** (`MOD97`), cards (Luhn),
IPs, MAC and IMEI, number plates in the current and older formats, VIN, towns, ethnic groups,
religions, parties, trade unions, ICD-10 codes, medicines, blood groups, benefits and PNC identifiers.

**Type** classifiers rule data classes out where the column cannot hold the data: an e-mail is text of
at least 5 characters, a birth date a date, timestamp or text, an amount a number.

**Padded values.** Discovery tests values as the database hands them over, without trimming them, and
databases pad: a CHAR column fills a value with spaces, and a code kept as text often comes with zeros
on the left. Every value pattern first removes the surrounding spaces, and patterns of digits also
accept zeros on the left — except the phone pattern, since a zero-filled ten-digit number (an NHS
number) would look like a UK phone; the NHS check digit is computed after the extra zeros are cleaned
away. The rules are shared by every preset, in [`_lib/detect.mjs`](../_lib/detect.mjs).

## Masking

All algorithms are deterministic for the engine's key, so the same value masks the same way in every
table and every job. Placeholders such as `N/A` or `-` do not fail a row: where there is nothing to
mask they pass through. Padding stays where it is.

Where an algorithm that comes with Delphix already does the job, the policy uses it instead of building
its own: **CM Numeric** for amounts, **Credit Card** for card numbers, **BloodType SL** for blood
groups ([`_lib/engine-algorithms.mjs`](../_lib/engine-algorithms.mjs)). For the IBAN it uses the
plugin's **IBAN** framework, which recomputes the check digits.

### Check digits

The plugin's Check Digit writes eleven minus the remainder, and a `0` both for ten and for eleven.
Neither UK rule fits that alone, so both chains use the technique of the Peruvian DNI: an **auxiliary
Check Digit with doubled weights** tells remainder 0 from remainder 1, and a Regex Decompose writes the
true digit.

- **NHS number** (`UK_NHS_NUMBER`, six steps): mask the nine digits (keeping the first; a CHI keeps a
  valid day and month), write the check digit, widen, auxiliary, resolve — remainder 0 gives `0`,
  remainder 1, which the rule never issues, is marked — then the ninth digit of a marked number moves
  up by one and the check digit is computed again. About one body in eleven is moved, so a few
  different numbers may mask alike (`verify.mjs` allows 3% fewer distinct outputs; it saw none).
- **UTR** (`UK_UTR_DIGITS`, four steps): the check digit is the **first** digit (weights 6 7 8 9 10 5 4
  3 2 on the other nine; remainder 0 gives 2, remainder 1 gives 1, otherwise eleven minus the
  remainder). The chain writes it at index 0 and the auxiliary at index 1.

### L1 — Direct identifiers

| Data class | Masking |
|---|---|

| `UK_L1_UTR` | Nine digits masked, the leading check digit recomputed; spacing and `K` kept |
| `UK_L1_GIVEN_NAME`, `UK_L1_SURNAME` | Word by word from UK given-name and surname lists; a hyphen kept |

| `UK_L1_EMAIL` | Name and domain mapped character by character, top-level domain `.test` |
| `UK_L1_PHONE` | `+44` or the trunk `0`, the next two digits and separators kept, the rest masked |
| `UK_L1_ADDRESS` | A fictitious UK address: number and street, flat in a named building, or house name |
| `UK_L1_SORT_CODE` | The bank (first two digits) kept, the branch masked |
| `UK_L1_IBAN` | The plugin's IBAN framework: sort code and account masked, check digits recomputed |

| `UK_L1_GEOLOCATION` | Integer part and first decimal kept (about 11 km), the rest masked |

### L3 — Special category data (Article 9)

Racial or ethnic origin, political opinions, religious or philosophical beliefs, trade union
membership, genetic data, biometric data and sex life or sexual orientation — and gender identity,
protected by section 22 of the Gender Recognition Act 2004. Categorical columns keep their shape: a
yes/no flag stays a flag in the same vocabulary, a numeric code gets other digits, and any other value
is replaced from the 2021 census categories (ethnic group, religion, sexual orientation, gender
identity) or from the parties of the four parliaments. Beliefs, trade union and sex life are
suppressed to `Not stated`; biometric and genetic data become `X`.

### HEALTH — Data concerning health (Article 9)

Health record identifiers, ICD-10 codes, SNOMED CT concepts and diagnoses, medications, blood group
(BloodType SL, which comes with the engine) and disability are replaced within their vocabulary;
clinical notes go through the free-text chain; reproductive and mental health are suppressed. The NHS
number is in L1.

### FIN — Financial data

Not special category, but under the banker's duty of confidence and the Consumer Credit Act 1974.
Credit files and insolvency (scores keep their digits' shape, statuses are replaced), debt, income,
assets and pensions (the engine's CM Numeric, which keeps the order of magnitude), DWP, HMRC and
council benefits — several of which reveal a disability — deprivation indices and housing tenure.

### PENAL — Criminal offence data (Article 10; DPA 2018 s. 11(2))

Alleged offences and proceedings count too. Records are replaced by a generic status (spent and
unspent convictions, cautions, no further action), flags kept as flags; PNC, crime and court
references masked character by character; DBS certificate numbers get other digits and levels and
outcomes are replaced.

## Postcodes and towns

The **postcode** keeps its outward code (`SW1A`), a district of thousands of addresses — the level at
which the ONS and the NHS publish — and masks the inward code (`2AA`) within the letters postcodes use.

The policy carries the 4,643 places of the GeoNames list of towns and cities of more than 1,000 people,
with their local authority (185 councils, unitary authorities and counties) and population. GeoNames
gave a district's population to a few villages (Saint Peters in Kent, Coity, Kempston Hardwick), and
filed Loughton under Shropshire; [`build.mjs`](build.mjs) works from the corrected list in
`source/places.tsv`. A place under 20,000 people becomes the main town of its local authority — the
largest one, or the county town where GeoNames' largest is not a real town (Maidstone for Kent, Truro
for Cornwall, Taunton for Somerset, Stornoway for the Western Isles). 3,963 places are generalized.
The main towns keep their names, even the small ones (Lerwick, Kirkwall); parts of London of fewer than
20,000 people become London. A name shared by several places is kept when any of them is large, and
another writing (`St Ives` for `Saint Ives`) is added only where no place has that name.

## Limits

- **Binary columns** (scans of passports, licences and residence permits, photographs, custody images,
  clinical PDFs in BLOBs) cannot be masked by these algorithms. Inventory them and report them as
  residual risk.
- **Places under 1,000 people** are not in the table: a column of hamlets is found by its name, but its
  values pass unchanged.
- **The NHS repair step** can make two NHS numbers mask alike; check uniqueness where the NHS number is
  a key. A CHI keeps a valid date, but no longer the one of the birth date column.
- **No check digit is recomputed** for passports, permits or licences.
- **Data Cleansing leaves unknown values as they are**: a town spelled in a way that is not in the list
  passes unchanged.
- **Free text**: up to four spaced identifiers per value, then word by word.
- **Colour and trade words are surnames** (Brown, Green, Gray, White, Baker, Cook): with the essential
  pack alone, a column of such words may be taken for names.
- **Children**: a birth date moves at most 60 days; split the rule by age group with Multi-Column
  Condition where crossing 13, 16 or 18 matters.
- **The engine key** links masked values back to production for whoever holds both; keep it away from
  the users of the masked copy.

## Checking

```bash
node presets/uk-gdpr-dpa-2018/build.mjs
node presets/uk-gdpr-dpa-2018/verify.mjs
node presets/_doc/build.mjs uk-gdpr-dpa-2018
```

The last one regenerates the PDFs; run it after any change to the policy or to `doc/`. To check every
preset at once, see [`verify-all.sh`](../README.md#checking-every-preset).

`verify.mjs` reviews every classifier configuration, profiles 168 columns with the whole policy at its
threshold — well named, badly named, the short names of packaged systems and 36 columns that are not
personal data — and audits the generalization table for all 4,643 places. It then masks the sample
values, the placeholders and each of the 105 algorithms' own sample input through the running app
(`DLPX_URL`, default `http://localhost:3000`), checking outputs against their vocabulary and every
masked NHS number, UTR and IBAN against its check digits, and 150 National Insurance and NHS numbers
for collisions. Each value forks a JVM.

The same columns are profiled again as a database may hand them over — CHAR values padded with spaces,
codes of digits with zeros on the left — and must land on the same data class; every sample value is
masked padded the same way too, and must come out as the bare value does.
