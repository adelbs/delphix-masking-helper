# Jamaica — Data Protection Act, 2020

A discovery policy that finds Jamaican personal data in a database and masks it, built for the
Data Protection Act, 2020, in operation since 1 December 2023. The goal is a non-production copy that
no longer identifies anyone: not only the direct identifiers, but the quasi-identifiers that
re-identify people in combination, the sensitive personal data of section 2 — which in Jamaica
includes **filiation**, and a definition of **biometric data** that names the photograph, height, eye
colour and blood type — health, offences and their proceedings, and financial data.

The Act is the closest a preset of this repository has to a direct mandate for masking test copies:
the seventh standard names **pseudonymisation and encryption** among the security measures a
controller must take (s. 30(6)), and using any means to breach the pseudonymisation applied to
personal data is an offence of its own (s. 30(7)).

## Detection

Every data class has a **Path** classifier on the column name, in English and in the abbreviations of
Jamaican systems (`TRN`, `NIS_NO`, `NIN`, `NHF_CARD_NO`, `NHT_NUMBER`, `DOB`). Names that are ambiguous
on their own (`NAME`, `RESULT`, `CITY`, `PARTY`, `TENURE`) carry a lower strength and need the values to
agree; generic ones exclude what they are not (`PRODUCT_NAME`, `MESSAGE_ID`, `PARTY_ID`).

Where the values have a recognizable shape or vocabulary, a **Regex** or **List** classifier finds
the data in columns whose name says nothing (`FIELD1`, `PFNOM`, `REMARKS`): TRNs, given names and
surnames, full names, e-mail, 876 and 658 phone numbers, addresses with a street, a Kingston postal
zone or a district and post office, cards (Luhn), IPs, MAC and IMEI, private and commercial plates,
VIN, titles by volume and folio, towns, ethnic groups, religions, parties, trade unions, filiation,
eye colours, ICD-10 codes, medicines, blood groups, NIS benefits and social programmes.

**Type** classifiers rule data classes out where the column cannot hold the data: an e-mail is text of at
least 5 characters, a birth date a date, timestamp or text, an amount a number.

**Padded values.** Discovery tests values as the database hands them over, without trimming
them, and databases pad: a CHAR column fills a value with spaces, and a code kept as text often comes
with zeros on the left. Every value pattern first removes the surrounding spaces, and patterns of
digits also accept zeros on the left. Lists of single words are looked up word by word, which drops
the padding; lists of multi-word values (towns, categories) are **Regex** classifiers whose pattern
holds the values as a prefix tree, case-insensitive also for accented letters — named `… - Values`.
The rules are shared by every preset, in [`_lib/detect.mjs`](../_lib/detect.mjs).

## Masking

All algorithms are deterministic for the engine's key, so the same value masks the same way in
every table and every job. Placeholders such as `N/A` or `-` do not fail a row: where there is
nothing to mask they pass through.

Padding stays where it is. Spaces around a value are kept, and zeros on the left are not masked: a
Regex Decompose pattern that starts with a digit keeps them in a group of their own, and the
Character Mappings run with `preserveLeadingZeros`. So `0012345678` masks as `00` followed by what
`12345678` masks to, and a value in a zero-filled CHAR column still joins its twin kept as a number.

Where an algorithm that comes with Delphix already does the job, the policy uses it instead of
building its own: **CM Numeric** for amounts, **Credit Card** for card numbers, **BloodType SL** for
blood groups ([`_lib/engine-algorithms.mjs`](../_lib/engine-algorithms.mjs)).

### L1 — Direct identifiers

| Data class | Masking |
|---|---|
| `JM_L1_TRN` | The nine digits mapped digit by digit, separators kept; one-to-one |
| `JM_L1_DRIVERS_LICENCE` | The same mapping as the TRN, which the licence carries: both still match |
| `JM_L1_GIVEN_NAME`, `JM_L1_SURNAME` | Word by word from Jamaican given-name and surname lists; a hyphen kept |
| `JM_L1_FULL_NAME` | Given names and surname in English order, a middle initial and `SURNAME, GIVEN` too |
| `JM_L1_EMAIL` | Name and domain mapped character by character, top-level domain `.test` |
| `JM_L1_PHONE` | `+1`, the area code (876, 658) and separators kept, the seven digits masked |
| `JM_L1_ADDRESS` | A fictitious Jamaican address: street and Kingston zone, lot in a housing scheme, or district and post office |
| `JM_L1_PAYMENT_CARD` | Credit Card, which comes with the engine (Luhn stays valid, the first six digits — the issuer — kept) |
| `JM_L1_IP_ADDRESS` | Each IPv4 octet mapped to 1–254 |
| `JM_L1_LICENCE_PLATE` | Category letters kept, digits masked |
| `JM_L1_LAND_TITLE` | Volume and folio numbers masked, the words kept |
| `JM_L1_GEOLOCATION` | Integer part and first decimal kept (about 11 km), the rest masked |
| `JM_L1_FREE_TEXT` | Free Text Redaction: TRNs, e-mail, phones, cards, plates, IPs, names |
| `JM_L1_CREDENTIAL` | Every character becomes `X` |
| NIS number, passport, voter ID, immigration document, civil registry, bank account, device, VIN, contract, user and address detail data classes | Character Mapping: vowels to vowels, consonants to consonants, digits to digits; hex kept hex for devices |

### L2 — Quasi-identifiers

| Data class | Masking |
|---|---|
| `JM_L2_BIRTH_DATE` | Shifted up to 60 days |
| `JM_L2_EVENT_DATE` | Death, marriage, hiring, admission, arrest and similar dates, shifted up to 30 days |
| `JM_L2_BIRTH_YEAR` | The decade stays, the last digit is masked |
| `JM_L2_AGE` | The decade stays (37 → 3x); 100 and over becomes 90 |
| `JM_L2_TOWN` | Towns under 10,000 inhabitants (2022 census) become the capital of their parish |
| `JM_L2_SEX` | Replaced within its own vocabulary |
| `JM_L2_DEPENDANTS` | Capped at 5 |
| neighbourhood, nationality, marital and union status, occupation, employer, education, school | Replaced from a list |

### L3 — Sensitive personal data (section 2)

Genetic and biometric data, filiation, racial or ethnic origin, political opinions, religious,
philosophical and similar beliefs, trade union membership and sex life — and, beyond the list,
gender identity. Section 2 counts the photograph, height, eye colour and blood type as biometric
data, so height (`JM_L3_HEIGHT`: unit and first figure kept) and eye colour have data classes of their
own, and a photograph column is redacted with the other biometric data.

Categorical columns keep their shape: a yes/no flag stays a flag in the same vocabulary, a numeric
code gets other digits, and any other value is replaced from a list of the category (the ethnic
groups and religions of the census, the two governing parties). Where the values share no
vocabulary — beliefs, trade union, sex life — they are suppressed to `Not stated`. Biometric and
genetic data become `X`. Sexual orientation is treated as sex life: in Jamaica it also exposes people
to the criminal law.

### HEALTH — Physical or mental health or condition (s. 2 (e))

Health identifiers (NHF, JADEP, medical record), ICD-10 codes and diagnoses, medications, blood group
(BloodType SL, which comes with the engine) and disability are replaced within their vocabulary;
clinical notes are redacted; reproductive and mental health are suppressed.

### FIN — Financial data

Not sensitive under the Act, but confidential under the Banking Services Act, 2014 and the Credit
Reporting Act, 2010. Credit references (scores keep their digits' shape, statuses are replaced), debt,
income, assets and pensions (masked by the engine's own CM Numeric, which keeps the order of
magnitude), NIS benefits, PATH and other social programmes, poverty status and quintiles, and housing
tenure.

### PENAL — Offences and proceedings (s. 2 (g))

The alleged commission of an offence is sensitive, whatever the outcome: records and proceedings are
replaced by a generic status, flags kept as flags; case numbers masked character by character.

## Towns

The policy carries the population of the 140 towns of the 2022 census list. 116 have fewer than 10,000
inhabitants; those that are not a parish capital — 111 — become the capital of their parish
(Kingston, Half Way Tree, Spanish Town, May Pen, Mandeville, Black River, Savanna-la-Mar, Lucea,
Montego Bay, Falmouth, St. Ann's Bay, Port Maria, Port Antonio, Morant Bay). The capitals keep their
names, even the small ones, and stand for the parish; the parish itself is kept, since the smallest,
Hanover, has about 70,000 people. Common spellings (`St Ann's Bay`, `Sav-la-Mar`, `Halfway Tree`,
`Mobay`) are recognized.

## Limits

- **Binary columns** (scans of the TRN card, licence or passport, photographs, fingerprints, clinical
  PDFs in BLOBs) cannot be masked by these algorithms. Inventory them and report them as residual risk.
- **Communities smaller than the census towns** are not in the table: a column of rural districts is
  found by its name, but its values pass unchanged. Generalize it to the parish where it sits next to a
  birth date and sex.
- **No check digit is recomputed**: none is published for the TRN or the NIS number. Company TRNs are
  masked too.
- **Passport, NIS, permit and voter numbers** have no public format and are masked character by
  character.
- **Data Cleansing leaves unknown values as they are**: a town spelled in a way that is not in the
  list passes unchanged.
- **Free text** is redacted token by token: a phone written with spaces is not found there.
- **Colour words are surnames** (Brown, Black, Green, Grey): with the essential pack alone, a column of
  eye colours is taken for names.
- **Minors** are persons under 18 under the Act: a birth date moves at most 60 days, so few people
  cross their 18th birthday — but some do. Split the rule by age group with Multi-Column Condition
  where that matters.
- **The engine key** links masked values back to production for whoever holds both; keep it away from
  the users of the masked copy.

## Checking

```bash
node presets/jamaica-dpa-2020/build.mjs
node presets/jamaica-dpa-2020/verify.mjs
node presets/_doc/build.mjs jamaica-dpa-2020
```

The last one regenerates the PDFs; run it after any change to the policy or to `doc/`. To check every
preset at once, see [`verify-all.sh`](../README.md#checking-every-preset).

`verify.mjs` reviews every classifier configuration, profiles 157 columns with the whole policy at its
threshold — well named, badly named, the short names of packaged systems and 33 columns that are not
personal data — and audits the generalization table for all 140 towns. It then masks the sample
values, the placeholders and each of the 83 algorithms' own sample input through the running app
(`DLPX_URL`, default `http://localhost:3000`), checking outputs against their vocabulary, 150 TRNs
for collisions, and that a TRN and a driver's licence with the same number mask alike. Each value
forks a JVM.

The same columns are profiled again as a database may hand them over — CHAR values padded with
spaces, codes of digits with zeros on the left — and must land on the same data class; every sample
value is masked padded the same way too, and must come out as the bare value does, around the spaces
and after the zeros.
