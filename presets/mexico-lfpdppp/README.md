# Mexico — LFPDPPP

A profile set that finds Mexican personal data in a database and masks it, built for the
[Ley Federal de Protección de Datos Personales en Posesión de los Particulares](https://www.diputados.gob.mx/LeyesBiblio/pdf/LFPDPPP.pdf)
(DOF 20 March 2025, last amended 14 November 2025). Processing data for a purpose outside the
privacy notice needs new consent (art. 11), and data subjected to prior *disociación* do not need
consent at all (art. 9, III). The goal is a non-production copy that no longer identifies anyone:
not only the direct identifiers, but the quasi-identifiers that re-identify people in combination,
the sensitive data of article 2, section VI, and the financial and patrimonial data that article 7
puts under express consent.

|---|---|
| Profile set | `MX - LFPDPPP - Datos personales`, assignment threshold 60 |
| Contents | 83 domains, 153 classifiers, 154 algorithms, 97 files |

## Detection

Every domain has a **Path** classifier on the column name, in Spanish, in the abbreviations of
Mexican systems (`AP_PATERNO`, `FEC_NAC`, `NUM_EXT`, `CVE_MUN`, `SDI`, `SBC`), in the attribute names
of CFDI 4.0 invoices (`RfcReceptor`, `DomicilioFiscalReceptor`, `RegimenFiscalReceptor`) and in
English. Names that are ambiguous on their own (`NOMBRE`, `EXPEDIENTE`, `RESULTADO`, `CIUDAD`) carry
a lower strength and need the values to agree; generic ones exclude what they are not
(`NOMBRE_PRODUCTO`, `CLAVE_PROD_SERV`, `CARGO_FIJO`, `DIRECCION_IP`).

Where the values have a recognizable shape or vocabulary, a **Regex** or **List** classifier finds
the data in columns whose name says nothing (`CAMPO1`, `OBS`, `TEXTO_LIBRE`): CURP, RFC, INE voter
key, NSS (Luhn), CLABE, names and surnames, e-mail, Mexican phone numbers, addresses (including
block and lot), cards (Luhn), IPs, MAC and IMEI, plates, VIN, school codes, municipalities,
indigenous peoples and languages, CIE-10 codes, medicines, blood groups, religions, parties, AFOREs,
social security institutions, social programs, case numbers.

**Type** classifiers rule domains out where the column cannot hold the data: a CURP is text of at
least 18 characters, an NSS 11, a birth date a date, timestamp or text.

## Masking

All algorithms are deterministic for the engine's key, so the same value masks the same way in
every table and every job. Placeholders such as `S/D` or `-` do not fail a row: where there is
nothing to mask they pass through, and text in a key column that does not have the expected shape
is masked character by character instead of being left as it was.

### L1 — Direct identifiers

| Domain | Masking |
|---|---|
| `MX_L1_CURP` | Letters, birth date, sex, state, consonants masked; **valid check digit**; one-to-one |
| `MX_L1_RFC` | Person (13) and company (12): same treatment, **valid modulo 11 check digit** (`A` included); agrees with the CURP |
| `MX_L1_NSS` | Payment Card: another number with a **valid Luhn check digit** |
| `MX_L1_CLABE` | Bank code kept, plaza and account masked, valid check digit (3-7-1) |
| `MX_L1_CLAVE_ELECTOR` | Consonants, date, state, sex and differentiator masked, same date as the CURP |
| `MX_L1_NOMBRE`, `MX_L1_APELLIDO` | Word by word from Mexican given-name and surname lists |
| `MX_L1_NOMBRE_COMPLETO` | Given names and both surnames, in Mexican order; `APELLIDOS, NOMBRES` too |
| `MX_L1_EMAIL` | Name and domain mapped character by character, top-level domain `.test` |
| `MX_L1_TELEFONO` | Subscriber digits masked; `+52`, the old mobile `1` and the area code kept |
| `MX_L1_DIRECCION` | A fictitious Mexican street address, with interior numbers and block and lot |
| `MX_L1_TARJETA` | Payment Card (Luhn stays valid) |
| `MX_L1_IP` | Each IPv4 octet mapped to 1–254 |
| `MX_L1_PLACA` | Letters among the plate alphabet (no `I`, `O`, `Q`), digits among digits |
| `MX_L1_GEOLOCALIZACION` | Integer part and first decimal kept (about 11 km), the rest masked |
| `MX_L1_TEXTO_LIBRE` | Free Text Redaction: CURP, RFC, voter key, e-mail, phones, NSS, cards, plates, IPs, names |
| `MX_L1_CREDENCIAL` | Every character becomes `X` |
| INE credential, passport, immigration, professional license, driver's license, e.firma, bank account, device, VIN, contract, user and address detail domains | Character Mapping: vowels to vowels, consonants to consonants, digits to digits; hex kept hex for devices |

### L2 — Quasi-identifiers

| Domain | Masking |
|---|---|
| `MX_L2_FECHA_NACIMIENTO` | Shifted up to 60 days |
| `MX_L2_FECHA_EVENTO` | Death, hiring, IMSS registration, admission and similar dates, shifted up to 30 days |
| `MX_L2_ANIO_NACIMIENTO` | The decade stays, the last digit is masked — same mapping as the year inside a CURP |
| `MX_L2_EDAD` | The decade stays (37 → 3x); 100 and over becomes 90 |
| `MX_L2_MUNICIPIO`, `MX_L2_CLAVE_MUNICIPIO` | Municipalities under 20,000 inhabitants (2020 census) become the nearest municipality of the same state with at least 20,000 |
| `MX_L2_LOCALIDAD` | The name of a municipality of over 100,000 |
| `MX_L2_COLONIA` | A common colonia name |
| `MX_L2_CODIGO_POSTAL` | The first three digits stay, the last two become `00` |
| `MX_L2_SEXO` | Replaced within its own vocabulary; `H`/`M` agrees with the sex inside CURP and voter key |
| `MX_L2_DEPENDIENTES` | Capped at 5 |
| nationality, marital status, occupation, employer, schooling, school | Replaced from a list |
| `MX_L2_CCT` | Character Mapping, format kept |

### L3 — Sensitive data (art. 2, VI)

The categories of the law — racial or ethnic origin, present and future health, genetic
information, religious, philosophical and moral beliefs, political opinions, sexual preference —
and, because the list is not exhaustive, gender identity, sexual life, biometrics and union
membership. Union membership was named by the 2010 law and is not by the 2025 text; it stays in
the set.

Categorical columns keep their shape: a yes/no flag stays a flag in the same vocabulary, a numeric
code gets other digits, and any other value is replaced from a list of the category (indigenous
peoples, indigenous languages, CIE-10 codes and diagnoses, medicines, disability categories of the
census, religions of the census, parties). Where the values share no vocabulary — reproductive and
mental health, sexual life, philosophical beliefs, union membership — they are suppressed to
`Sin información`. Biometric and genetic data become `X`.

### FIN — Financial and patrimonial data (art. 7)

Credit bureau records (MOP codes stay MOP codes), debt, monthly income, daily wage (SDI/SBC), assets
and retirement savings (mapped into plausible ranges), AFORE, housing credit, social security
coverage, social programs, AMAI socioeconomic level, housing tenure and SAT tax regime (replaced
within their own notation).

### PENAL — Criminal records

Records replaced by a generic status, flags kept as flags; case and investigation folder numbers
masked character by character.

## Check digits

The plugin's own frameworks cover two keys: Check Digit computes the CLABE's weighted sum of digits,
and Payment Card keeps the NSS valid, since its check digit is Luhn. Neither can do the CURP or the
RFC: Check Digit reads letters in base 36 (the CURP table puts `O`–`Z` one higher), writes a modulo 11
result of 10 as `0`, and does not accept `&` or `Ñ`. For those two, the set computes the check digit
two characters at a time: after the body is masked, a running sum travels through the value, each
step a Data Cleansing table that turns *sum + next two characters* into *those characters + new
sum*, and the last one writes the check digit in place. Each table lists only what its positions can
hold, so the CURP takes 8 steps and the RFC 6, in a single String Algorithm Chain (the engine allows
eight).

The cost is per value and per step. Measured with the plugin outside the engine, on a laptop, with
200,000 values: Character Mapping about 2.2 µs a value, NSS 2.7, RFC 8.8, CURP 11.5 — of which 6.3
is the body (the date and the keyed lookups for sex and state). A first version that read one
character per step took 14.8 µs for the CURP.

Every masked CURP, RFC and NSS is valid and the mapping is one-to-one. The birth date inside CURP,
RFC and voter key is masked by Numeric Mapping within valid ranges of month and day, so it is always
a real date and two dates never collide; the same algorithm masks it in the three keys, which keep
agreeing with each other.

## Limits

- **Binary columns** (photos of INE credentials, fingerprints, clinical PDFs in BLOBs) cannot be
  masked by these algorithms. Inventory them and report them as residual risk.
- **Keys and their sources**: the letters of a masked CURP or RFC no longer derive from the masked
  name, and its date is not the masked birth date column.
- **Inconvenient words**: a masked CURP may start with a letter combination RENAPO would have
  replaced. It still passes the check digit.
- **Lowercase or formatted keys** (a CURP in lower case, an NSS with dashes) are masked character by
  character without a valid check digit.
- **Data Cleansing leaves unknown values as they are**: a municipality spelled in a way that is not
  in the list passes unchanged. A name shared by a large and a small municipality stays; a 3-digit
  municipality code without its state is not generalized.
- **Free text** is redacted token by token: a phone written with spaces is not found there, and a
  given name that is also a common word (`Luz`, `Paz`, `Rosa`) is redacted wherever it appears.
- **Minors**: a birth date moves at most 60 days, so few people cross their 18th birthday — but
  some do. Where that matters, split the rule by age group with Multi-Column Condition.
- **Addresses** are replaced as a whole line. Street, colonia, postal code and municipality kept in
  separate columns are masked independently.
- **Plates and VINs** keep their format, not the state series or the VIN check digit.

## Checking

```bash
node presets/mexico-lfpdppp/build.mjs
node presets/mexico-lfpdppp/verify.mjs
node presets/_doc/build.mjs mexico-lfpdppp
```

The last one regenerates the PDFs; run it after any change to the set or to `doc/`.

`verify.mjs` reviews every classifier configuration, profiles 151 columns with the whole set at its
threshold — well named, badly named and 26 columns that are not personal data — and masks 350
sample values and 228 placeholders through the running app (`DLPX_URL`, default
`http://localhost:3000`), including 60 random CURPs, 60 RFCs, 40 NSS and 30 CLABEs checked for a
valid check digit. It then masks 150 of each key to check that none collide, and 20 CURP and RFC
pairs of the same person to check they still share their first ten characters. Each value forks a
JVM: the algorithm check takes about ten minutes.
